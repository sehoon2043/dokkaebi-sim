# 도사 수첩 개편: 사냥터별 추천 빌드 (설계)

작성 2026-10-22. 사이트 주인(길드장)과 대화로 정한 내용. 개인 정보(길드원 닉네임 등)는 넣지 않는다.

## 1. 왜 바꾸나

- 10/21 도술 밸런스 패치 직후, 사이트 추천(트리 탭 23개: 몰이 3, 원거리 단일 4, 절명 2, 보스 6, 스타일별 사냥 3, 커뮤니티 5)으로는 빌드를 고르기 어려웠다. 같은 날 유튜브·커뮤니티(깨비지지 덱 게시판, 디시 갤)에서 실제로 돌려 본 빌드의 반응이 더 좋았다.
- 길드원이 사이트를 여는 순간은 "지금 가는 사냥터에서 뭘 쓸까"다. 그런데 지금 탭은 사냥터와 연결이 안 되고, 실전에서 검증된 빌드가 계산 결과 사이에 묻힌다.
- 상위 사냥터(예: 260k 음산한 폐광)에서는 스펙이 모자라면 광역 몰이가 버거워서 유지력(회복·보호막)이 중요해진다. 그래서 같은 사냥터라도 스펙에 따라 생존/믹스/딜 중 맞는 걸 알려 줘야 한다.

성공: 길드원이 사이트를 열고 사냥터 → (광역/단일) → 카드 3장만 보고 바로 빌드를 고른다. 고른 빌드가 저장되어 다음에도 바로 보인다.

## 2. 목표

1. 사이트를 **탭 2개**로 나눈다: **[내 수첩]**(입력) / **[추천 빌드]**. PC에서도 탭으로 나눈다(지금은 PC 두 패널, 휴대폰만 탭).
2. 추천 빌드 탭은 **A안**: 사냥터 선택 → **광역 | 단일** 선택(저장) → **생존 · 믹스 · 딜** 카드 3장.
3. 카드마다 **사이트 계산 1위**와 **커뮤니티 빌드**를 함께 보여 주고, 본인이 [이걸로]를 눌러 고른다. 고른 빌드는 **사냥터별 '내 빌드'**로 저장한다(예전 프리셋 대신).
4. 전투력·공격력을 입력받아 사냥터마다 **'내 스펙 추천'** 표시(생존/믹스/딜 중 하나)를 붙인다. 판정은 전투력(사냥터 기준 전투력과 비교), 기준은 디시 사냥 후기 + 길드원이 남긴 결과로 다듬는다. 공격력은 회복·보호막량 계산에 쓴다.
5. 도술은 **아이콘**으로 사용 순서대로 보여 준다.

## 3. 하지 않는 것

- 휴대폰 화면 최적화(길드원은 주로 PC). 좁은 화면에서는 카드를 세로로 쌓아 깨지지만 않게 한다.
- 몹 체력·공격력 데이터 수집(구할 곳이 없음).
- 저장 서버·로그인 방식 교체(Vercel `dosa-api` + Upstash 그대로, 닉네임 + 고정 PIN 0000 그대로).
- 패치노트·커뮤니티 소식·길드원 현황 기능 변경(그대로 둔다).

## 4. 실패로 보는 것

- 다시 탭·카드가 많아져 한 화면에 수십 개가 쏟아지는 것. 한 사냥터 화면의 기본 상태는 카드 3장(+접힌 목록)까지.
- 커뮤니티 빌드가 계산 결과에 묻혀 안 보이는 것.
- '생존' 카드인데 실제로는 회복이 거의 안 되는 빌드를 내미는 것(예: [기세]를 거는 도술 없이 얼음창·회전 난격 회복을 셈하는 것. 표식 연계는 `도술_정보.md` 5장 기준).
- 공개 저장소·Actions 실행 기록·공개 JSON에 닉네임 같은 개인 정보가 남는 것.

## 6. 사용자가 정한 것

- 화면은 **A안**: 사냥터 선택 → 광역/단일 → 생존·믹스·딜 카드 3장, 도술은 아이콘.
- **탭 2개**: 도술 레벨 적는 탭 / 추천 빌드 탭.
- **사냥터**: 황무지, 우물(215k 우물동굴), 폐광(260k 음산한 폐광), 비경 3종(이름은 사용자가 알려 줌), 보스.
- **등급**: 생존 / 믹스 / 딜. **광역/단일**은 따로 고른다(광역 좋아하는 사람, 단일 좋아하는 사람이 다 있어서).
- **입력 스펙**: 전투력, 공격력. (처음엔 공격력·방어력으로 정했다가 바꿈: 10/21 21시 디시 수집분 250글 중 사냥터가 나오는 98글에서 방어력이 적힌 글은 0개, 공격력 11개, 전투력 29개였고 사냥터 이름도 215k·260k처럼 전투력 기준이라서.)
- **스펙별 사냥터 정보**: 디시 글에서 긁어 온다.
- **'내 스펙 추천' 판정**: 전투력으로 한다(사냥터 기준 전투력과 비교, 디시 후기로 기준 조정). 공격력은 회복·보호막량 계산에 쓴다.
- **선택 저장**: [이걸로], 광역/단일, 돌려 본 결과는 **누르는 즉시 저장**한다. 이때 추천 트리 재계산은 돌지 않는다(저장 서버에 '재계산 없는 저장'을 추가해 배포).
- **생존·믹스 카드의 계산 1위**: 딜 손해 한도 안에서 유지력(초당 회복·보호막)이 가장 큰 조합. 생존은 딜 1위 대비 −10% 안, 믹스는 −5% 안.
- **카드 후보**: 사이트 계산 1위와 커뮤니티 빌드를 **둘 다** 보여 주고 본인이 고른다. 고른 것은 저장한다(프리셋이 없어졌으니 그 대신).
- **커뮤니티 빌드가 여러 개일 때**: 카드에는 가장 잘 맞는 1개, 나머지는 "커뮤니티 빌드 N개 더 ▾"로 펼친다.
  - 분류: 사냥터 = 덱 제목·본문 키워드(우물·215k·폐광·260k·황무지·비경·보스 등), 광역/단일 = 범위 도술(대상 2명 이상) 개수, 생존/믹스/딜 = 힐·보호막 도술 개수(2개 이상 / 1개 / 0개). 사냥터가 안 적힌 덱은 사냥터 칸에 넣지 않고 맨 아래 '사냥터 미지정 커뮤니티 빌드' 목록에만.
  - 순서: ① 10/21 패치 이후 글만 ② 내가 가진 도술로 바로 쓸 수 있는 것 먼저(아니면 '안 배운 도술 N개' 표시) ③ 추천 수 많은 순(비추천이 많으면 감점).
  - 각 빌드에 작성자, 추천 수, 영상 링크(본문에 있으면), 계산 1위 대비 %.
- **주 사용 기기**: PC.

## 7. 화면

### 7-1. 추천 빌드 탭
- 맨 위 사냥터 칩: [황무지] [우물] [폐광] [비경 ×3] [보스]. 마지막으로 본 사냥터를 기억한다.
- 그 아래 [광역 | 단일]. 고른 쪽은 수첩 data에 저장된다.
- 카드 3장(생존 · 믹스 · 딜), PC에서 가로로 나란히. 카드 하나:
  - 머리: 등급 이름, '내 스펙 추천'(해당 등급이면), '내 빌드'(이 사냥터에서 고른 빌드가 이 카드에 있으면).
  - 후보 ① 사이트 계산 1위: 짧은 이름(핵심 도술), 수치 한 줄(처치 속도·몰이 점수 비교, 공격력이 있으면 '초당 회복·보호막 약 N'), 아이콘 행, [이걸로].
  - 후보 ② 커뮤니티 빌드 1개: '커뮤니티' 표시, 작성자·추천 수·영상 링크, 계산 1위 대비 %, 안 배운 도술 표시, 아이콘 행, [이걸로].
  - "커뮤니티 빌드 N개 더 ▾": 같은 형식의 접힌 목록.
- 아이콘 행: 사용 순서대로, 왼쪽 위 번호, 궁극기 금색 테두리, 힐 초록 테두리, 마우스를 올리면 도술 이름. 시안 A안 크기(32px 안팎).
- 맨 아래: '사냥터 미지정 커뮤니티 빌드' 접힌 목록.

### 7-2. 내 수첩 탭
- 지금 왼쪽 패널 내용(강화 레벨, 보유 도술 + 각성, 도술 칸 수, 허수아비 실측 기록, 메모).
- 새로: 전투력·공격력 칸(기존 `stats.power`·`stats.atk`를 다시 보이게. 다른 능력치 칸은 계속 숨김).
- 새로: **내 빌드 목록** — 사냥터별로 고른 빌드(아이콘 행 + 출처), 그 옆에 "돌려 본 결과" 한 줄(물약 썼는지, 분당 엽전, 분당 처치). 결과는 스펙 추천 근거로도 쓴다. 고르거나 결과를 적으면 바로 저장된다(8장).

## 8. 저장 (수첩 data에 추가)

- `prefStyle`: "광역" | "단일"
- `mybuilds`: { 사냥터 키: { tier: "생존"|"믹스"|"딜", style, from: "calc"|"comm", commId?, order: [...], ult, slots: [...], pickedAt, result?: { potion: bool, coinPerMin?, killPerMin?, at } } }
- 전투력·공격력은 기존 `stats.power`·`stats.atk`를 그대로 쓴다. 이 둘은 계산에 들어가므로 바꾸면 지금처럼 [저장] → 재계산.
- **즉시 저장(재계산 없음)**: 저장 서버 `dosa.js`에 새 요청 `{a: "pick", nick, pin, prefStyle?, mybuilds?}`을 추가한다.
  - PIN 확인 → 프로필 data의 `prefStyle`·`mybuilds`만 바꿔 저장 → `updatedAt`은 그대로, GitHub 분석 요청(dispatch)도 하지 않는다.
  - 크기 한도(45,000자) 확인은 save와 같게.
  - 사이트는 [이걸로]·광역/단일·결과 입력 때 이 요청을 바로 보내고, 화면의 다른 수정(저장 안 한 것)은 보내지 않는다.
  - 배포: `server`에서 `npx vercel deploy --prod --yes`(Vercel 계정 sehoon2043, 프로젝트 `dosa-api`). 이 PC에 Vercel 로그인이 안 돼 있으면 사용자가 `npx vercel login`을 한 번 해야 한다.

## 9. 계산 (analyze.py 결과에 추가)

- 결과에 `grounds`를 추가한다: { 사냥터 키: { name, styles: { 광역: { 생존: {calc, comm: [...]}, 믹스: {...}, 딜: {...} }, 단일: {...} }, specTier? } } 와 `unassigned`(사냥터 미지정 커뮤니티 덱). 사이트는 `grounds`가 있으면 새 화면, 없으면(예전 결과) 예전 화면이나 "다시 계산 중" 안내.
- **유지 도술**: 조건 없이 회복·보호막을 주는 도술. 생명의 흐름(공격력 12% × 5, 쿨 15초), 생명의 축복(35%, 20초), 방패 밀기(보호막 70%, 15초), 방패 충격파(자신·아군 보호막 35%, 20초), 강인한 의지(보호막 35% + 받는 피해 −20%, 30초). 조건부 회복(기세·낙인·질풍·수호가 있어야 나오는 얼음창·회전 난격·찌르기 등)은 그 표식을 거는 도술이 트리에 있을 때만 센다(`도술_정보.md` 5-2).
- **유지력 점수**: 5분 계산에서 유지 도술 시전 횟수 × 1회량(공격력 배수)의 합 ÷ 시간 = 초당 '공격력의 N%'. 공격력을 알면 초당 회복·보호막 수치로 보여 준다. 시전 횟수는 몰이·필드 계산에서 센다(지금 모델은 안 셈 → 세도록 추가).
- 등급별 계산 1위를 고르는 기준(사용자 결정: 딜 손해 한도 안에서 유지력 최대):
  - **딜**: 유지 도술 0개 중 딜 1위(광역 = 몰이 점수, 단일 = 처치 속도).
  - **믹스**: 유지 도술 1개인 조합 중, 딜 카드 대비 −5% 안에서 유지력이 가장 큰 것. 그런 조합이 없으면 유지 도술 1개 중 딜 1위.
  - **생존**: 유지 도술 2개 이상인 조합(힐 2, 힐 + 보호막, 힐 2 + 보호막 모두 포함) 중, 딜 카드 대비 −10% 안에서 유지력이 가장 큰 것. 없으면 유지 도술 2개 이상 중 딜 1위.
  - 광역은 몰이 모델, 단일은 필드 모델(원거리·절명 근접 모두 후보). 힐은 사용 순서 맨 앞(지금 규칙 그대로).
  - 카드 수치 한 줄: 딜 카드 대비 딜 %, 유지력(초당 공격력의 N% 또는 수치).
- 보스: 딜 = `boss`(스타일별 보스 중 1위), 생존·믹스는 힐을 넣은 보스 트리(새로 계산). 광역/단일 선택은 숨긴다.
- 사냥터마다 계산 1위가 달라질 근거가 지금은 거의 없다(몹 정보 없음). 처음에는 황무지·우물·폐광의 계산 1위가 같아도 된다. 사냥터 차이는 커뮤니티 빌드, 내 스펙 추천, 사냥터 후기에서 생긴다.
- 비경: 몹이 모이는 곳이라 광역 = 몰이 모델(공간 결계 모으기 보정 포함) 그대로.
- 계산을 바꾸면 `ENGINE`을 올리고 `tools/check.py`에 점검을 더한다.
- **정기 재계산**(내가 정함): 새 커뮤니티 덱·새 후기가 저장 안 한 사람에게도 반영되도록, 하루 두 번 정기 실행(9시·21시) 때 내용 있는(배운 도술이 있는) 프로필은 모두 다시 계산한다. `stale()`에 "결과가 12시간보다 오래됨"을 더하는 식. 저장 직후 실행·즉시 저장(`pick`)은 지금처럼.

## 10. 내 스펙 추천 (전투력 → 등급)

- **사냥터 표**(관리자가 고치는 작은 표, 저장 서버 `d:grounds`): 사냥터 키, 이름, 기준 전투력(이름에 있는 값: 우물동굴 215k, 음산한 폐광 260k, 황무지·비경은 사용자가 알려 주거나 후기로 채움), 광역 기본 여부, 보스 여부.
- **처음 판정**(후기가 모자랄 때): 내 전투력 ÷ 기준 전투력 = r.
  - r ≥ 1.05 → 딜, 0.95 ≤ r < 1.05 → 믹스, r < 0.95 → 생존. (경계값은 내가 정한 시작값, 후기가 쌓이면 조정)
  - 전투력을 안 적었거나 기준 전투력이 없는 사냥터는 표시하지 않는다.
- **사냥 후기 기록** 한 건: {사냥터, 전투력, 공격력(있으면), 광역/단일, 빌드 요약, 물약 사용(예/아니오/언급 없음), 분당 엽전, 분당 처치, 출처(디시 글 번호·링크 또는 '길드원'), 날짜}. 닉네임은 남기지 않는다.
- 수집:
  - 디시: 커뮤니티 소식 자동 수집에 '사냥 후기 뽑기' 단계를 더한다. 같은 수집 글에서 Claude(sonnet)가 위 항목을 JSON으로 뽑는다. 사냥터나 전투력이 없는 글은 버린다.
  - 길드원: 내 빌드의 "돌려 본 결과"를 분석 때 함께 모은다(닉네임 빼고, 그 사람의 전투력과 함께).
- **후기로 다듬기**: 그 사냥터에 '물약 없이 돈' 후기가 3건 이상이면, 그 후기들 전투력의 하위 25% 값을 기준 전투력 대신 쓴다. 물약 이야기가 없는 후기는 '물약 없이' 근거로 세지 않는다(내가 정함).
- 후기 기록은 저장 서버 관리자 데이터(`d:hunting`)에 두고 analyze가 읽는다. 공개 저장소·공개 JSON에는 두지 않는다.

## 11. 비경 3종

사용자가 이름을 알려 줄 예정. 그전에는 칩에 '비경'을 하나로 두거나 숨긴다.

## 12. 만드는 순서 (제안)

1. 화면 1단계: 탭 2개 + A안 추천 빌드 탭 + 아이콘 + 내 빌드 즉시 저장(`pick`, 서버 배포 포함). 계산은 유지 도술 개수·딜 손해 한도 규칙으로 등급별 1위를 만들고 `grounds`를 채운다(사냥터마다 같은 계산 1위여도 됨). 커뮤니티 덱 분류·순서 규칙 적용. 정기 재계산.
2. 전투력·공격력 입력 + 유지력 수치 + 사냥터 표(`d:grounds`) + 처음 판정(전투력 비율)으로 '내 스펙 추천' 표시.
3. 사냥 후기 수집(디시 + 길드원 결과)으로 기준 다듬기.
4. 비경 3종 이름 반영, 보스 생존·믹스 트리.

## 13. 내가 정한 것 (사용자 확인용)

- 물약 이야기가 없는 후기는 '물약 없이' 근거로 세지 않는다.
- 힐 2개 + 보호막 조합도 생존 후보에 넣는다.
- 정기 실행 때 내용 있는 프로필은 모두 다시 계산한다(결과가 12시간보다 오래되면).
- 처음 판정 경계값: 내 전투력이 사냥터 기준의 105% 이상이면 딜, 95~105%면 믹스, 95% 미만이면 생존.
- 보스는 광역/단일 선택을 숨기고 딜 카드는 스타일별 보스 1위.
- 비경 3종은 이름을 받기 전까지 '비경' 칩 하나(몰이 모델).

## 14. 만드는 사람이 정할 것

- 카드 세부 디자인(색, 간격, 펼치기 방식), 칸 배치(하단 5칸)를 보여 주는 방식.
- 예전 결과(`trees`만 있는 결과)와의 전환 처리.
- 커뮤니티 덱을 몇 페이지까지 받을지(분류 후 사냥터마다 충분하도록).
- 사이트 패치노트 문구(개인 기준 문구 없이, 버전 +0.1).
